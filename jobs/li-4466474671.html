Description

Websites are crucial for businesses—helping them get found and chosen online. Yet for many small businesses, websites become a burden. They launch with high hopes, spending countless hours on every little detail, aiming for perfection. But soon after launch... no more updates. The website sits untouched, slowly becoming outdated, broken, and buried by search engines, eventually joining the ranks of the "living dead" websites in the vast online cemetery.

To address this issue, CentralApp (soon rebranding to https://stride-site.com/ ) is moving away from a template-first approach (such as Wordpress or Wix) and is developing an innovative method for website creation. This new approach integrates numerous pre-designed business modules, alongside a branding engine that offers millions of possibilities. This combination aims to deliver an optimal design and content with minimal effort.

Our solution is currently used by thousands of businesses across Europe, mostly in France, Belgium, Italy & Spain.

In addition to our website product, we offer a suite of tools designed to enhance your impact: an Integration Marketplace, Advanced Website Forms, Client inbox & clients list, Local SEO with Listing Management, an Instagram Wall, and a Review Wall.

What will you be doing? This is not a narrow frontend role or backend role We are looking for a Product Engineer who can take an ambiguous product problem and drive it to production: clarify the user experience, define the expected behavior, prototype quickly, implement the frontend, shape the API contract, and work with backend owners to ship the full solution.

Your strongest execution layer should be backend & dev ops. You should be able to review Haskell code independently and maintain a high bar on performance, accessibility, maintainability, and product correctness.

You do not need to be a production front-end engineer aswell (AI will do the translation, or frontend focused colleague can help) but you do need to be able to reason about front-end constraints, including UX and be able to implement Front-end parts of the project you will work on.

Current stack Our backend includes Haskell services and Node.js

Our frontend stack includes: React, including server-side rendering and Node.js

Our infra is AWS focused.

Responsibilities As a Product Engineer, you will:

  • Turn ambiguous product problems into clear user flows, product behavior, edge cases, and success criteria
  • Build and maintain scalable, modular, high-performance frontend code
  • Review backend and frontend implementation independently across UX, code quality, performance, accessibility, maintainability, and product correctness
  • Define API contracts and backend expectations clearly
  • Collaborate with backend engineers on architecture, data models, permissions, error handling, observability, and performance
  • Use AI tools to accelerate prototyping, implementation, refactoring, testing, debugging, and technical exploration
  • Critically review AI-generated output and stay accountable for correctness, maintainability, and product quality
  • Balance speed, simplicity, performance, maintainability, and user experience
  • Keep the end user, business impact, SEO, accessibility, and product quality in mind

Requirements We are looking for a Product Engineer who can operate like a one-person product strike team when needed.

This role is for you if

  • You want to own outcomes end to end: clarify the problem, define the product behavior, implement the frontend, coordinate backend work (or even develop it depending on which service we need to act on), and ship
  • You are strong enough in frontend to review React code independently, while also reasoning about APIs, data models, permissions, backend constraints, and edge cases
  • You use AI to move faster, but still trace the logic, adapt the output to the codebase, and verify the result before it reaches review

This role is not for you if

  • You want a pure frontend implementation role with detailed tickets, finalized designs, and predefined APIs
  • You expect product managers, designers, or backend engineers to make the hard product and technical decisions before you start
  • You prefer narrow specialization, heavier process, or avoiding ownership of backend or UX constraints, edge cases, and AI-assisted output quality
