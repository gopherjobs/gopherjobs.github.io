Description

Who We Are We’re doxy.me (doc-see-me), the world's most loved telemedicine solution, and we're on a mission to connect the world to the future of healthcare.

We believe that cost and complexity should never be a barrier to telemedicine. That’s why we created a simple, free, and secure telemedicine platform. Since 2013, we’ve grown to more than 1 million healthcare providers from 180+ countries who have clocked over 8 billion minutes of telemedicine sessions to date.

Our goal is to deliver the future of healthcare to every patient and healthcare professional on earth. Help us get there by joining our team of innovators, dreamers, and doers.

We’re a remote-first company with regional hubs for in-person collaboration (Charleston, SC, Salt Lake City, UT & London, UK).

The role This is a software engineering role with security as the domain, not a security role with some scripting attached.

We are building internal security platforms, such as SecurityOS and our Trust Engine, that run the security program for our product, with AI doing much of the work that used to be manual. SecurityOS is in production today, Trust Engine is next, and there is more to come.

The security team at doxy.me is becoming an engineering team. We build and run these platforms, we build and govern the AI agents that operate inside them, and we ship the product security work for doxy.me's telehealth platform as part of the same practice. You would be an early engineer on that team with a direct hand in what these platforms become.

We are looking for someone with a founder mindset: you see what should exist, you design it, you build it, and you ship it. You can own a problem end to end without a spec handed to you. You have taste about what makes software good and opinions about how security should be done, and you can back both with working code.

What You'll Build And Do

  • Design and build core SecurityOS capabilities: domain modules, integrations with the systems that feed the platform (identity, endpoints, cloud, code, ticketing), the event model that connects them, and the reporting and console layer on top. Production TypeScript and Node, shipped to real users on the security team.
  • Build and govern AI agents that operate inside the platform: define what they can do, what context they get, how their actions are controlled and audited, and how they go through the same front door as a human user.
  • Own product security for doxy.me's telehealth platform as an embedded engineer: threat modeling with product teams, design and code review, and fixing or building the thing yourself when that is the fastest path.
  • Build the security tooling and guardrails that make the right thing the default in our stack, as code our engineers actually use, not as policy documents.
  • Automate the security SDLC. You know how to threat model, review a design, review code for security flaws, and run security testing by hand. Your job is to build the platform and automation that does that work at scale, so it is not done by hand.
  • Shape the roadmap. You will have real influence over what SecurityOS becomes and how the security function at doxy.me operates.

Who You Are Must-haves

  • You can build and ship software. You have taken something from an idea to running in production, maintained it, and had other people depend on it, in TypeScript and Node or a comparable stack. We care that you can design a system from the data model up and get it live, not how many years you have been doing it. If AI tools are a big part of how you build, good. That is how we build too.
  • You have real depth in application and product security: secure SDLC, threat modeling, secure design and code review, OWASP and how vulnerabilities actually get authored and designed out. You need this to be able to build software that does it. Knowing it is table stakes; building it is the job.
  • You have built things nobody asked you to build because you saw they were needed, and they got used.
  • You can take an ambiguous problem, form a point of view, and drive it to working software without a spec or a ticket.
  • You have opinions about how a security program should run and you are not attached to the way it has always been done.
  • You are comfortable building with and around AI: using it as a core part of how you work, and designing systems where agents are first-class actors with controls on what they can do.
  • You can talk to product engineers as a peer. They should see you as one of them who happens to know security deeply.

Nice-to-haves

  • Startup or founding experience, or a side project you took seriously enough to ship.
  • Healthcare, HIPAA, or other regulated-industry context.
  • AWS, Kubernetes, and infrastructure as code. Useful, but we are not hiring for this.
