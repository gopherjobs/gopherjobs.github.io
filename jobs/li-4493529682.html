Description

The client is an AI infrastructure company that builds platforms for some of the world's largest model-training and inference workloads. They're adding 2–3 Storage Engineers to build and run a homegrown inference caching layer, including KV-cache offload and reuse. This is a hands-on role: about 50% building systems and 50% running them in production. You'll work on multi-petabyte storage that sits directly on the inference critical path.

What you'll do

  • Build caching and data-movement layers that deliver KV cache and model weights into GPU memory at fabric speed (including GPU-direct / RDMA).
  • Design KV-cache offload and reuse across GPU HBM, host memory, local NVMe and distributed cache, and integrate it with inference engines such as vLLM, SGLang and TensorRT-LLM.
  • Operate, scale and tune parallel file systems and object stores (Vast, Weka, Ceph, Lustre) for 10–50 GB/s per node.
  • Build Kubernetes-native storage operators and controllers for automated provisioning, multi-tenancy, performance isolation and quotas.
  • Investigate production issues across the storage stack, network and code, and ship the fixes.
  • Benchmark and profile end-to-end data paths, and contribute to open-source storage and inference projects.

What you need

  • Strong C++ or Go, used to build production systems (not only scripts): storage services, Kubernetes operators, or performance-critical data paths.
  • Strong Python.
  • Strong distributed-systems background, ideally in storage, with hands-on depth in at least one of:
  • distributed or parallel file systems: Ceph, WekaFS, Lustre, Vast, GPFS
  • S3-compatible object storage: Ceph RGW, MinIO, R2
  • adjacent distributed systems: databases, distributed file systems or search infrastructure
  • A track record of building systems and solving hard problems with measurable results, such as better throughput, latency, reliability or cost.
  • Experience debugging production issues across the Linux storage stack (ext4/xfs, NVMe, RAID), the network and the code, then shipping a fix.
  • Ownership of both development and operations, and willingness to join the on-call rotation (every engineer is on it; overtime is compensated).

Nice to have

  • KV-cache, inference infrastructure, caching or other latency-sensitive data paths. Not required: strong storage and distributed-systems engineers are very welcome.
  • Experience at AI-native or GPU-cloud companies building inference stacks.
  • Kubernetes, virtualized infrastructure and storage/caching technologies.

How it works

  • Full-time (40h/week), remote. Start within 2–3 weeks.
  • You start as a contractor through Lemon.io for 3–6 months, with a possible path to direct hire by the client: salary, startup equity, health insurance and other benefits, plus remote flexibility.
  • Long-term engagement (7+ months, ongoing).
  • Interview process: an intro call and a technical interview with Lemon.io, then 2–3 client rounds: a manager loop and a technical loop that includes an AI-assisted (vibe-coding) round.
